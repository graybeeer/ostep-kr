# 개요

[English 원문](README.md)

> 예제 C 코드·명령·출력은 원문을 보존했습니다. `prompt>`는 셸 프롬프트이며 입력하지 않습니다.

이 숙제는 잠금과 조건 변수로 생산자/소비자 큐를 구현한 실제 코드를 살펴봅니다. 여러 설정으로 실행하면서 어떤 구현이 올바르고 어떤 구현에 문제가 있는지, 그리고 세부적인 동작 차이가 무엇인지 익힙니다.

각 버전은 생산자/소비자 문제를 서로 다른 방법으로 “해결”합니다. 대부분은 잘못된 구현이고 하나만 올바릅니다. 문제의 정의와 코드의 기본 동작은 교재의 해당 장을 먼저 읽어 보세요.

코드를 받은 뒤 `make`로 네 가지 버전을 빌드합니다.

- `main-one-cv-while.c`: 조건 변수 하나를 사용합니다.
- `main-two-cvs-if.c`: 조건 변수 두 개를 사용하지만 기다려야 하는지 `if`로 검사합니다.
- `main-two-cvs-while.c`: 조건 변수 두 개를 사용하고 `while`로 검사합니다. 올바른 버전입니다.
- `main-two-cvs-while-extra-unlock.c`: 위 버전과 비슷하지만 채우기·꺼내기 함수 주변에서 잠금을 놓았다가 다시 획득합니다.

공통 코드가 있는 `pc-header.h`와 빌드 방법이 있는 `Makefile`도 함께 살펴보세요.

프로그램의 옵션은 다음과 같습니다.

- `-l <생산자별 생성 항목 수>`
- `-m <공유 생산자/소비자 버퍼 크기>`
- `-p <생산자 수>`
- `-c <소비자 수>`
- `-P <생산자의 각 지점별 잠들기 시간을 지정하는 문자열>`
- `-C <소비자의 각 지점별 잠들기 시간을 지정하는 문자열>`
- `-v`: 상세 실행 흐름을 출력합니다.
- `-t`: 전체 실행 시간을 측정해 출력합니다.

`-l`은 각 생산자의 반복 횟수, 즉 생성할 데이터 항목 수입니다. `-m`은 1 이상의 공유 버퍼 크기이며, `-p`와 `-c`는 각각 생산자와 소비자 수입니다.

더 흥미로운 것은 생산자와 소비자의 잠들기 문자열입니다. 특정 실행 지점에서 스레드를 재워 다른 스레드가 실행할 기회를 줄 수 있습니다. 이를 통해 각 구현의 문제를 드러내거나 생산자/소비자 문제의 다른 특성을 관찰할 수 있습니다.

생산자가 세 명이라면 각 생산자의 설정을 콜론으로 구분합니다.

```sh
  sleep_string_for_p0:sleep_string_for_p1:sleep_string_for_p2
```

각 생산자의 문자열 안에서는 쉼표로 각 지점의 잠들기 시간을 구분합니다. 이를 이해하기 위해 `main-two-cvs-while.c`의 생산자 코드를 보겠습니다. 생산자 스레드는 반복하며 `do_fill()`로 공유 버퍼에 항목을 넣습니다. 채우기 함수 주변에는 버퍼가 가득 찼을 때 기다리고 소비자에게 신호를 보내는 코드가 있습니다. 자세한 원리는 교재를 참고하세요.

```c
void *producer(void *arg) {
    int id = (int) arg;
    int i;
    for (i = 0; i < loops; i++) {   p0;
        Mutex_lock(&m);             p1;
        while (num_full == max) {   p2;
            Cond_wait(&empty, &m);  p3;
        }
        do_fill(i);                 p4;
        Cond_signal(&fill);         p5;
        Mutex_unlock(&m);           p6;
    }
    return NULL;
}
```

코드의 `p0`, `p1` 등의 표시는 잠들기 시간을 삽입할 수 있는 지점입니다. 여기에는 나오지 않은 소비자 코드에도 `c0` 등 같은 종류의 지점이 있습니다.

생산자 설정은 `p0`부터 `p6`까지 각 지점에서 얼마나 잘지를 지정하면 됩니다. 예를 들어 `1,0,0,0,0,0,0`은 매 반복에서 잠금을 얻기 전인 `p0`에서 1초 잠들고 나머지 지점에서는 잠들지 않게 합니다.

이제 실행 출력을 봅시다. 생산자와 소비자는 각각 하나이고, 기본 동작대로 추가적인 잠들기는 사용하지 않습니다. 버퍼 크기는 2입니다(`-m 2`).

먼저 빌드합니다.

```sh
prompt> make
gcc -o main-two-cvs-while main-two-cvs-while.c -Wall -pthread
gcc -o main-two-cvs-if main-two-cvs-if.c -Wall -pthread
gcc -o main-one-cv-while main-one-cv-while.c -Wall -pthread
gcc -o main-two-cvs-while-extra-unlock main-two-cvs-while-extra-unlock.c -Wall -pthread
```

그다음 실행합니다.

```sh
prompt> ./main-two-cvs-while -l 3 -m 2 -p 1 -c 1 -v
```

동작을 설명하기 전에 왼쪽의 공유 버퍼 표기를 읽어 봅시다. 처음에는 비어 있으며 `---`가 빈 칸을 뜻합니다. 빈 칸 두 개는 `[*--- --- ]`로 표시됩니다. 버퍼에 들어 있는 항목 수인 `num_full`도 처음에는 0입니다. P0이 값을 하나 넣으면 `[u 0 f--- ]`로 바뀌고 `num_full`은 1이 됩니다.

`u`는 `use_ptr`의 위치, 즉 다음 소비자가 값을 꺼낼 칸입니다. `f`는 `fill_ptr`의 위치, 즉 다음 생산자가 값을 넣을 칸입니다. `*`는 두 포인터가 같은 칸을 가리킨다는 뜻입니다.

오른쪽에는 생산자와 소비자가 다음에 실행할 단계가 표시됩니다. 예를 들어 생산자가 잠금을 얻고(`p1`), 빈 칸이 있으므로 값을 넣습니다(`p4`). 이어 잠금을 놓는 지점(`p6`)까지 진행한 뒤 다시 잠금을 얻으려 합니다. 이 예제에서는 소비자가 먼저 잠금을 얻어 값을 소비합니다(`c1`, `c4`). 나머지 흐름도 따라가며 생산자와 소비자가 하나씩 있을 때의 동작을 이해해 보세요.

이번에는 잠들기를 추가해 실행 순서를 바꿔 봅시다. 소비자가 먼저 실행할 수 있도록 생산자를 재우려면 다음과 같이 실행합니다.

```sh
prompt> ./main-two-cvs-while -l 1 -m 2 -p 1 -c 1 -P 1,0,0,0,0,0,0 -C 0 -v

The results:
 NF             P0 C0
  0 [*---  --- ] p0
  0 [*---  --- ]    c0
  0 [*---  --- ]    c1
  0 [*---  --- ]    c2
  0 [*---  --- ] p1
  1 [u  0 f--- ] p4
  1 [u  0 f--- ] p5
  1 [u  0 f--- ] p6
  1 [u  0 f--- ] p0
  1 [u  0 f--- ]    c3

  0 [ --- *--- ]    c0
  0 [ --- *--- ]    c1

```

생산자는 `p0`에서 잠들기 설정의 첫 값 1을 읽고, 잠금을 얻으려 하기 전 1초 동안 잠듭니다. 따라서 소비자가 먼저 실행해 잠금을 얻습니다. 하지만 큐가 비어 있으므로 조건 변수를 기다리며 잠금을 놓고 잠듭니다. 이후 생산자가 실행하고 나머지 동작이 진행됩니다.

잠들기 옵션을 지정할 때는 생성한 생산자 또는 소비자 각각에 대한 문자열을 제공해야 합니다. 예를 들어 `-p 2 -c 3`이면 생산자 두 명, 소비자 세 명의 설정이 필요합니다. `-P 0:1` 또는 `-C 0,1,2:0:3,3,3,1,1,1`처럼 지정할 수 있습니다. 각 문자열의 항목 수는 코드의 잠들기 지점 수보다 짧아도 됩니다. 생략된 뒤쪽 지점은 0으로 초기화됩니다.
