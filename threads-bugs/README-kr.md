# 개요

[English 원문](README.md)

> 예제 명령은 원문을 보존했습니다. `prompt>`는 셸 프롬프트이며 입력하지 않습니다.

이 숙제는 C로 작은 벡터 객체를 구현하면서 교착 상태를 피하는 여러 방법을 실험합니다. 벡터 객체의 기능은 `add()`와 `init()` 정도로 제한적이며, 여러 교착 상태 회피 방법을 보여 주기 위한 예제입니다.

모든 변형에서 공통으로 사용하는 다음 파일들을 먼저 살펴보세요.

- `common_threads.h`: pthread 등의 라이브러리 호출을 감싸서 실패를 놓치지 않게 하는 래퍼입니다.
- `vector-header.h`: 벡터의 고정 크기와 벡터 하나를 나타내는 `vector_t` 구조체 등을 정의합니다.
- `main-header.h`: 여러 프로그램이 공유하는 전역 변수를 담습니다.
- `main-common.c`: 옵션을 해석하는 `main()`을 담습니다. 벡터 두 개를 초기화하고, `worker()`를 실행하는 스레드들을 만들어 벡터에 접근하게 한 뒤 여러 `vector_add()` 호출이 끝나기를 기다립니다.

각 변형은 `vector_add()`라는 벡터 덧셈 함수 안에서 동시성을 다르게 처리합니다. 아래 파일의 코드를 읽어 동작을 이해하세요. 각 파일은 위의 공통 파일들과 함께 하나의 실행 가능한 프로그램을 구성합니다.

- `vector-deadlock.c`: 목적지(dst), 원본(src) 순서로 잠금을 획득합니다. 한 스레드가 `vector_add(v1, v2)`를 호출하고 다른 스레드가 동시에 `vector_add(v2, v1)`을 호출하면 교착 상태가 생길 수 있습니다.
- `vector-global-order.c`: 벡터 주소를 기준으로 정한 전체 순서에 따라 잠금을 획득합니다.
- `vector-try-wait.c`: `pthread_mutex_trylock()`으로 잠금 획득을 시도합니다. 실패하면 이미 가진 잠금을 모두 놓고 처음부터 다시 시도합니다.
- `vector-avoid-hold-and-wait.c`: 잠금을 획득하는 과정 전체를 별도의 단일 잠금으로 보호하여 점유 대기(hold and wait)가 발생하지 않게 합니다.
- `vector-nolock.c`: 잠금 대신 원자적 fetch-and-add로 `vector_add()`를 구현합니다. 그 결과 함수가 제공하는 동작 의미는 다른 버전과 조금 다릅니다.

`Makefile`을 읽고 `make`로 실행 파일 다섯 개를 빌드하세요.

```sh
prompt> make
```

그다음 원하는 프로그램 이름으로 실행합니다.

```sh
prompt> ./vector-deadlock
```

모든 프로그램은 같은 옵션을 받습니다. 자세한 처리는 `main-common.c`에 있습니다.

- `-d`: 교착 상태가 발생할 수 있는 호출 순서를 사용합니다. 스레드마다 번갈아 벡터 인자 순서를 뒤집습니다. 예를 들어 스레드가 두 개이면 스레드 0은 `vector_add(v1, v2)`, 스레드 1은 `vector_add(v2, v1)`을 호출합니다.
- `-p`: 두 벡터를 함께 쓰는 대신 각 스레드에 별도의 벡터 쌍을 줍니다. 같은 벡터에 대한 경합이 없을 때 성능이 어떻게 달라지는지 확인할 수 있습니다.
- `-n num_threads`: 생성할 스레드 수입니다. 이 예제에서 교착 상태를 만들려면 둘 이상이 필요합니다.
- `-l loops`: 각 스레드의 덧셈 호출 반복 횟수입니다.
- `-v`: 동작에 관한 상세 정보를 표시합니다.
- `-t`: 전체 실행 시간을 측정해 표시합니다.
