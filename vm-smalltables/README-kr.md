# 개요

[English 원문](README.md)

> 예제 표기·출력은 원문을 보존했습니다. 한글판에서는 설명 문구가 한국어로 표시됩니다. 실행 파일은 `paging-multilevel-translate.py`이며, `python3 paging-multilevel-translate.py`로 실행할 수 있습니다.

이 숙제는 다단계 페이지 테이블의 동작을 이해했는지 확인합니다. 재미있는 숙제라고 부를 수도 있지만, “재미있다”는 데 동의할지는 직접 풀어 보면 알겠지요!

기본 가정은 다음과 같습니다.

- 페이지 크기는 현실보다 훨씬 작은 32바이트입니다.
- 프로세스는 하나만 있다고 가정합니다. 가상 주소 공간은 1024페이지, 즉 32KB입니다.
- 물리 메모리는 128페이지로 구성됩니다.

따라서 가상 주소는 15비트입니다. 오프셋이 5비트, VPN이 10비트입니다. 물리 주소는 오프셋 5비트와 PFN 7비트를 합한 12비트입니다.

이 시스템은 다단계 페이지 테이블을 사용합니다. 가상 주소의 상위 5비트로 페이지 디렉터리를 찾습니다. 유효한 페이지 디렉터리 항목(PDE)은 페이지 테이블이 들어 있는 물리 페이지를 가리킵니다. 페이지 테이블 한 페이지에는 페이지 테이블 항목(PTE)이 32개 들어 있습니다. PTE가 유효하면 해당 가상 페이지에 대응하는 물리 프레임 번호(PFN)를 얻습니다.

PTE 형식은 다음과 같습니다.

```sh
  VALID | PFN6 ... PFN0
```

유효 비트 하나와 PFN 7비트를 합해 총 8비트, 즉 1바이트입니다.

PDE도 사실상 같은 형식입니다. 여기서 번호는 다음 단계 페이지 테이블이 있는 물리 페이지를 가리킵니다.

```sh
  VALID | PT6 ... PT0
```

문제를 시작할 때 두 가지 정보가 주어집니다.

첫째는 페이지 디렉터리 기준 레지스터(PDBR)의 값입니다. 페이지 디렉터리가 어느 물리 페이지에 있는지 알려 줍니다.

둘째는 모든 물리 페이지의 전체 메모리 내용입니다. 다음과 같이 표시됩니다.

```sh
    page 0: 08 00 01 15 11 1d 1d 1c 01 17 15 14 16 1b 13 0b ...
    page 1: 19 05 1e 13 02 16 1e 0c 15 09 06 16 00 19 10 03 ...
    page 2: 1d 07 11 1b 12 05 07 1e 09 1a 18 17 16 18 1a 01 ...
    ...
```

각 행은 페이지 0, 1, 2 등에 저장된 32바이트를 보여 줍니다. 페이지 0의 첫 번째 바이트(인덱스 0)는 `0x08`, 두 번째는 `0x00`, 세 번째는 `0x01`입니다.

이어서 변환할 가상 주소 목록이 주어집니다.

PDBR에서 출발하여 가상 페이지에 해당하는 디렉터리 항목과 페이지 테이블 항목을 찾아가세요. 유효 여부를 확인하고, 유효하다면 최종 물리 주소를 구합니다. 그 물리 주소를 이용하면 메모리 참조가 가져올 **데이터 값**까지 찾을 수 있습니다.

가상 주소가 유효하지 않아 변환에 실패할 수도 있습니다.

유용한 옵션은 다음과 같습니다.

```sh
  -s SEED, --seed=SEED       the random seed
  -n NUM, --addresses=NUM    number of virtual addresses to generate
  -c, --solve                compute answers for me
```

`-s`로 난수 시드를 바꾸면 다른 문제가 생성됩니다. `-n`으로 가상 주소 수를 늘리면 같은 메모리 내용에서 더 많은 주소 변환을 연습할 수 있습니다. `-c` 또는 `--solve`는 정답을 보여 줍니다.

복잡해 보이지만, 디렉터리 → 페이지 테이블 → 데이터 순서로 차근차근 따라가 보세요!
